The earlier R44 pin (`_lg_set_vm_display_live_attach`) only avoided the GPU bus when the `VFIO_LA_RESERVED_GUEST_BUSES` env var was set, and only the install paths set it — the toggle path (`profile_apply_mode`), the perf define, and `remove_looking_glass`'s restore never did, so a boot display could land on 0x06 and stay there.
  - fix: new shared `_la_repair_video_off_gpu_bus()` helper is a single backstop that runs on EVERY define of a live-attach VM. It reads the reserved GPU+audio guest buses DIRECTLY from the profile fragments (not only the env var — so the toggle/restore paths that do NOT export `VFIO_LA_RESERVED_GUEST_BUSES` still work) UNION the env var UNION the buses of PCI hostdevs still in the XML (the GPU when cold-attached), then re-pins the `<video>` boot display off any reserved bus to the smallest-index free non-reserved `pcie-root-port` (a port's child bus = its controller index in hex). Exit codes: 0 = re-pinned (file written); 3 = already safe / no-op (not a live-attach VM with a fragment, video=none, video already off every reserved bus, or an address-less video with no free reserved bus to proactive-pin); 1 = the video sits ON a reserved bus but no free non-reserved root-port was found (caller warns / skips the define).
